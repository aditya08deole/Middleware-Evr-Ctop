Deploying the CTOP Middleware

Three steps. Everything after step 2 is clicking buttons.

Why this page has no Deploy button

A page opened from a file cannot install software or change system settings — browsers block that on purpose, and it is a good thing they do. So step 2 starts a small tool on the server that has the permissions, and that tool gives you the buttons.

1 Put this folder on the server

Copy the zip across, then unpack it:

sudo mkdir -p /opt/ctop-middleware sudo chown $USER:$USER /opt/ctop-middleware unzip -o ~/ctop-middleware-*.zip -d /opt/ctop-middleware cd /opt/ctop-middleware chmod +x entrypoint.sh scripts/*.sh

unzip -o replaces the program files and leaves your settings and database alone.

2 Start the deployment tool

sudo python3 deploy-ui.py

It prints a web link. Open that link and you will see Check the server, Set up this server and Deploy now buttons, with the live output of each step and the final address of the running app.

If the server has no desktop, run this on your own computer first, then open the link there:

ssh -L 8099:127.0.0.1:8099 YOUR_USER@YOUR_SERVER

3 Press the buttons, in order

  • Check the server — confirms the settings files are present. Changes nothing.
  • Set up this server — first time only. Installs Docker, the firewall, restart-on-reboot, nightly backups and monitoring.
  • Deploy now — builds and starts the app, waits for it to answer, and puts the previous version back by itself if the new one will not start.

For later updates, only Deploy now is needed.

About encryption.key — read once

Three files hold your settings and are not in the zip: .env, service-account-key.json and encryption.key.

Copy them into the folder once, the very first time. After that every future zip leaves them untouched, because they are not inside the zip — so you never copy them again.

encryption.key cannot be replaced. It is the key that unlocks every device password already saved in the database. If it is lost or swapped for a new one, none of them can ever be read again and every device token has to be issued afresh. The tool records a fingerprint of it and refuses to deploy if it ever changes.

Full reference: DEPLOYMENT.md in this folder. Prefer the terminal? make deploy, make rollback, make status, make logs.
